# 图结构、身份和对账

SPU 是一组产品信息，SKU 是具体可售规格。节点名称可重复或改变，不能当身份。结构节点按 label + 业务 id MERGE，固定 independent-sample 数据集标记；同名不同品牌的两个“轻旅背包”保持不同 SPU ID。

graph/schema.py 列出 10 类结构节点（加入 Tag 后共 11 类）和 13 组允许关系；constraints.py 创建 IF NOT EXISTS 唯一约束。neo4j_writer 在同一事务内先匹配两端，再写允许的关系。返回输入、实际匹配与驱动创建计数，missing start/end 直接报错并回滚。重复记录去重有统计，不吞错误。

Tag 是带来源的文本提及，身份包含数据集、SPU ID、原文 hash 与 start/end；模型版本和来源字段存为属性。更改描述只替换目标 SPU 范围的旧提及，不删除其他商品标签。公开 4 个 Tag 的 model_sha256 明确写 manual fixture，不冒充权重摘要。

公开合成图实测：结构部分 21 节点、27 关系，加 4 个 Tag 和 4 条 Have，共 25/31。课程私有图的结构实测与静态前提分开保留，不能把课程 1529/1641 写成公开图运行结果。

同步必须处于 build 模式。服务前切换 serve，会重启专属实例、查询只读状态，并尝试写入后验证拒绝且不存在探针节点。system 库不在只读保护范围内；HTTP 从不接受原始查询。

真实测试分别检查只读 MySQL、节点数量、重复同步、改名稳定 ID 和事务回滚。执行环境变量与命令见 CONTRIBUTING；不要指向他人的数据库。
